title: Dispositions (field extractor)
description: Pull answers out of every call automatically — outcome, interest, callback time, anything you describe — and choose the model that reads the calls.
---

**Dispositions** are the answers Whispey pulls out of each call after it ends. You describe what you want to know, for example "Did the caller agree to a callback?", and every call gets a value for it. They show up as columns in [Call Logs](./call-logs), can be filtered and charted, and can trigger [flags](./call-logs#flags).

The same feature is called **Field Extractor** in Call Logs and **Dispositions** in Agent Studio. Both open the same settings.

## Open the settings

- In **Call Logs**, click **Field Extractor** at the top right.
- In **Agent Studio**, click **Dispositions** in the right panel. Here the labels say Dispositions instead of Field Extractor, for example **Enable Dispositions**.

Owners and admins can change them. Viewers do not see them by default. See [Team and roles](../workspace/team-and-roles).

## Add a field

Each field is one thing you want to know about a call.

1. Under **Extraction Fields**, type a **Label**. This becomes the column name, for example `callback_time`.
2. Type a **Description**. This is the instruction the model follows. Click the expand button to write a longer one.
3. Click **Add Field** for more.
4. Click **Save Field Extractor**.

The first time you set up fields, the switch at the top turns on by itself once a field has both a label and a description. If you turn it off yourself, it stays off. If you save with no complete fields, it saves as off.

:::tip
Say what answers you want. "Did the caller agree to a callback? Answer one of: Yes, No, Unclear" gives the same few values on every call, which keeps filters, charts and flag rules reliable. "Callback?" gives a different wording every time.
:::

To move fields between agents, use **Copy all** and **Paste all**. They copy the whole list as JSON.

## Choose the model

The **Model** menu picks which model reads each call.

| Model | Notes |
|---|---|
| **GPT-4.1 mini** | The default. Every agent uses it until you change it. |
| **GPT-5.6 Luna** | Thinks before it answers. Usually cheaper per call, and takes a few more seconds. |
| **GPT-5.6 Sol** | Beta. |
| **GPT-5.6 Terra** | Beta. |

Answers can differ between models, especially for judgement fields such as "was the booking handled correctly". After switching, check a few calls before you rely on the new values in flags, retries or reports. Picking **GPT-4.1 mini** again returns the agent to the default.

The model only applies to calls processed after you save. To fill in older calls with the new model, use **Re-analyze** in Call Logs.

## Use call details in a description

A description can include details from the call, such as the customer's name or the plan they are on.

1. Write the detail as a variable in double braces, for example `{{plan_name}}`.
2. Under **Dynamic Variables**, map it to where the value lives on the call, for example `metadata.plan_name` or `dynamic_variables.order_id`. **Map N detected** adds every variable your descriptions use.

Mapped details are also given to the model alongside the conversation.

## What the model reads

For each call, the model gets:

- Your fields and their descriptions.
- The conversation, one line per turn. Tool calls appear with their name and whether they worked, but not the data they returned. The agent's next reply usually says what happened.
- The mapped call details, if any.
- The date and time the call is processed. For a call being re-analyzed, that is the time of the re-analysis, not the time of the call. Avoid descriptions that depend on "today" or "tomorrow" if you plan to re-analyze old calls.

If the model cannot find an answer, the value is `N/A`.

## Where the values appear

| Place | What you see |
|---|---|
| [Call Logs](./call-logs) table | One **Dispositions** column per field. Pick them in **Columns**. |
| An open call | The **Dispositions** group in **Call data**. |
| Agent Studio | The values from the last call, right after it ends. |
| Filters | **Transcription** filters match on any field. |
| [Custom charts](./custom-charts) and [exports](./exporting-data) | Every field is available. |

Values arrive shortly after the call ends, once it has been processed.

## Change fields on past calls

New or changed fields only apply to calls processed after you save. To update calls you already have, open the three-dot menu in Call Logs and choose **Re-analyze**.
