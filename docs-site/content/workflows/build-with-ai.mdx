---
title: Build a workflow with any AI
description: Copy one prompt into ChatGPT, Claude or any AI, describe your agent, and paste the result into Whispey.
---

You can have any AI assistant write your workflow for you. You copy a ready-made prompt, add a few lines about your agent, and paste the answer into the editor.

This is useful when you want a first draft quickly, or you already work in ChatGPT, Claude or a similar tool. You can also use **Ask Pi** inside the editor, which does the same job without copying anything.

## Steps

1. Copy the prompt below. Use the copy button at the top right of the box.
2. Paste it into your AI assistant.
3. Replace the last line, **MY AGENT**, with a description of your agent. Say who it calls or answers, what it must do, which details it must collect, and how the call should end.
4. Send it. The AI replies with one block of JSON.
5. Copy that JSON.
6. In Whispey, open your workflow agent. Click the three dots in the top bar, choose **Paste flow from JSON**, paste, and click **Import to canvas**.
7. Click the red or grey problems button if it shows one, and follow the [checklist](./quickstart).

:::note
Pasting replaces whatever is on the canvas. If you want to keep your current flow, use **Copy flow as JSON** from the same menu first.
:::

## The prompt

```text
You are helping me build a voice agent in Whispey, a platform for AI voice agents. A Whispey "workflow" agent follows a path of steps. Turn my description at the bottom into ONE workflow as JSON that I can paste into the Whispey editor (the three-dots menu, then "Paste flow from JSON").

Reply with a single JSON code block, then one or two sentences saying what you built and anything I must fill in. Put no comments inside the JSON.

HOW A WORKFLOW WORKS
- A call starts at the "start" step and follows connections ("edges") from step to step until it reaches an "ending" step.
- Steps ("nodes") do small jobs: talk with the caller, collect details, choose a path, call another system, hand the call to a person, or end the call.

TOP-LEVEL FIELDS
schemaVersion: always "1.0"
metadata: { name, description }
agent: { globalPrompt, llm, stt, tts, languages, knowledge, advanced }
  globalPrompt: who the agent is, how it sounds and rules it must never break. It applies to every step. Always include a line like "Only do what the CURRENT step says, then move on."
  llm: use { "name": "azure", "model": "gpt-4.1-mini" }
  stt: use { "name": "sarvam", "model": "saaras:v4", "language": "unknown" }
  tts: use { "name": "elevenlabs", "voice_id": "MmQVkVZnQ0dUbfWzcW6f" }
  languages: [] unless I ask for several languages
  knowledge: { "enabled": true, "topK": 4 } only if the agent must answer questions from documents I will upload; otherwise { "enabled": false, "topK": 4 }
transports: { "web": { "enabled": true }, "telephony": { "enabled": true or false } }. Turn telephony on only for phone calls.
variables: [{ "key", "type": "string" | "number" | "boolean" | "object", "default"?, "description"? }]. Declare every detail you use as {{name}}.
start: the id of the first step. It must be the greeting step.
nodes: the steps (below).
edges: the connections (below).
globalRules: things that can happen at any point (below).

STEP TYPES (every step also has: id, name, stage, type, position { x, y })
- conversation: the agent talks with the caller. Fields: prompt (instructions), staticText (exact words to say, optional), skipUserResponse (true = say it and move on without waiting), blockInterruptions (optional).
- extract_variable: asks for details and remembers them. Fields: prompt, extractions: [{ variable, type, description, required }]. Set required to false for details that may not apply to every caller.
- logic_split: chooses a path from details already collected, saying nothing. Its paths are edges of kind "logic".
- function: calls another system. Fields: method, url, headers, body, waitMessage, saveAs.
- call_transfer: hands the call to a person (phone calls only). Fields: transferTo, mode ("cold" or "warm"), message.
- ending: ends the call. Field: message (the last thing to say, optional).
Only an extract_variable step can save what the caller says. A conversation step cannot, so never tell one to "save" or "set" a value.

CONNECTIONS (edges): { id, source, target, kind, condition?, expression?, label? }
- "always": go to the next step once the caller has replied. Use this between normal steps.
- "condition": go when what the caller says matches the text in "condition". Only from conversation or extract_variable steps.
- "logic": go when "expression" is true, for example age > 18. Only from a logic_split.
- "fallback": go when nothing else applies.

GLOBAL RULES: [{ "id", "target", "condition", "sources": [] }]
Use one for anything that can happen at any step: the caller asks for a human, describes an emergency, asks you to stop calling, is not interested, or it is a wrong number. "target" is the step to go to, usually an ending. Leave "sources" empty so it applies everywhere. Never draw the same condition as an edge from many steps.

DESIGN RULES
1. One step per phase of the call, not per sentence. Typical flow: 4 to 8 steps. Never more than 12 unless I ask.
2. Most steps have ONE outgoing "always" edge. Use "condition" edges only where the call truly goes a different way, usually 2 or 3. No step needs more than 4 outgoing edges.
3. Use few endings: one for a normal finish, plus one for each genuinely different farewell, such as a hand-off to a person.
4. Set "stage" on every step, such as Greeting, Request, Close, so the editor can group them.
5. Lay the steps out from left to right: start at x 0 and add 320 to x for each next step. Stack branches 160 apart in y. Put endings on the far right.
6. Give every step a short plain name and a unique id in kebab-case.
7. If you need a real value I did not give you (a web address, phone number or key), write "TODO: " and what is needed, and tell me in your reply.
8. Do not add steps, branches or details I did not ask for.
```

## What the prompt does

- It explains what a workflow is, so the AI does not need to know Whispey.
- It lists every field the editor expects, so the JSON is accepted when you paste it.
- It tells the AI to keep the flow small, to use global rules for things that can happen at any point, and to mark optional details as not needed.
- It includes a short example of the right size and shape.
- It asks the AI to write "TODO:" where it needs a real value, such as a web address, and to tell you.

## After you paste

1. **Read the flow.** Open the Outline in the side panel and check the steps are in the right order.
2. **Fix any TODO.** Open each step the problems list points at and fill in the real value.
3. **Check the greeting is the start.** The first step should show the green START label.
4. **Test it.** Deploy, then make a test call. See [Test, deploy and version history](./test-deploy).

## If the editor rejects the JSON

- **Not valid JSON.** Ask the AI to "reply with only valid JSON, with no comments and no trailing commas".
- **Missing fields.** Paste the error message back to the AI and ask it to fix the JSON.
- **The start does not point to a step.** Ask the AI to set `start` to the id of the greeting step.
